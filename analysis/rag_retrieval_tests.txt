RAG RETRIEVAL TESTS (Owner: Yashasvi)
=====================================

Setup
-----
- Policies: 8 synthetic policies (all synthetic=true)
    * 1 Medicare LCD-style policy (lumbar MRI, jurisdiction JK)
    * 7 commercial policies for fictional payer "SampleCommercial" (jurisdiction national)
- Chunks: 46 (split at each policy's section headings)
- Embeddings: sentence-transformers/all-MiniLM-L6-v2 (384-dim)
- Vector index: FAISS IndexFlatIP (cosine similarity on normalized vectors)
- Reranking: cross-encoder/ms-marco-MiniLM-L-6-v2 (on by default)
- Filters: payer, procedure code, jurisdiction (applied in code after ranking)
- chunk_id format: policy_id::section_slug (cited by config/criteria_rules.yaml)

Note on scores: with reranking on, scores are raw cross-encoder relevance scores,
not percentages. They can be negative. Only the order matters.


TEST 1: Medicare policy, procedure 72148 (lumbar MRI)
------------------------------------------------------
Command:
  python src/rag/rag_pipeline.py demo   (query 1: payer=Medicare, procedure=72148)
Query: "How many weeks of conservative treatment are needed before a lumbar MRI?"

  #1  score=6.1589  medicare_lcd_lumbar_mri::coverage_indications_limitations_and_or_medical_necessity
      section=Coverage Indications, Limitations, and/or Medical Necessity
  #2  score=4.6441  medicare_lcd_lumbar_mri::red_flag_conditions
      section=Red Flag Conditions

Result: PASS. The correct section (6 weeks of conservative management) is #1,
and the red-flag exception is #2.


TEST 2: SampleCommercial policy, procedure 72148

still in the top 3, which is why the agent reads the top 3 results.

Findings:
- Keyword search is best when the question reuses the policy's wording;
  embeddings are best on reworded questions.

- Section names help embeddings once policies share a common layout (15 vs 12).
